## Séquencement interne

Un microprocesseur est un **système préprogrammé** : il répond de façon prédéfinie aux ordres qui arrivent dans son **registre d’instruction** (RI). Un ordre est ici une instruction.

<Definition titre="Instruction">
    Une instruction est une **somme d’actions élémentaires**. Elle est formée d’un **code opératoire**, éventuellement suivi d’un ou plusieurs **opérandes**. Selon le processeur, sa taille va de **1 à 8 octets**.
</Definition>

## Exemple de programme Z80

| Instruction | Effet |
| --- | --- |
| `ADD A,B` | $A \leftarrow A + B$ |
| `LD A,3Ah` | $A \leftarrow 3Ah$ |
| `INC A` | $A \leftarrow A + 1$ |
| `NOP` | aucune opération |
| `JP 2025h` | $PC \leftarrow 2025h$ |

Sur le Z80, une adresse de 16 bits est rangée **octet de poids faible en premier** : `JP 2025h` s’écrit `C3h 25h 20h` en mémoire.

## Exemple d’ordre : additionner A et B

L’instruction `ADD A,B` additionne A et B et met le résultat dans A. Cette **seule instruction** correspond à **quatre actions élémentaires** :

1. envoyer A dans l’ALU ;
2. envoyer B dans l’ALU ;
3. lancer l’opération ADD ;
4. mettre le résultat dans A.

## Les trois phases d’une instruction

<Definition titre="Phase 1 — Recherche (OPCODE FETCH)">
    Le µP va chercher le code de l’instruction dans la **mémoire programme** (externe), puis il charge ce code dans son RI.
</Definition>

<Definition titre="Phase 2 — Décodage (DECODE)">
    L’**unité de contrôle** décode le code contenu dans le RI, puis elle repère dans sa table interne les **microcodes** (µcodes) de l’instruction.
</Definition>

<Definition titre="Phase 3 — Exécution (EXECUTE)">
    Le µP exécute les µcodes correspondants : il envoie des ordres à l’ALU, aux registres et à la mémoire.
</Definition>

Le µP enchaîne les trois phases, instruction après instruction : recherche, décodage et exécution de l’instruction $n$, puis recherche, décodage et exécution de l’instruction $n+1$, etc.

## Déroulement interne d’une instruction

Chaque instruction a sa propre suite de **microcodes**, rangée dans une table interne qu’utilise l’unité de contrôle.

1. Le registre d’instruction (RI) contient le code opératoire. Pour `ADD A,B`, RI = 80h.
2. L’unité de contrôle **décode le RI** et pointe sur le premier microcode de l’instruction dans la table des µcodes (qui contient, à la suite, les µcodes de `DEC A`, de `ADD A,B`, etc.).
3. L’unité de contrôle **pilote l’exécution séquentielle** des µcodes en envoyant les ordres aux sous-systèmes (ALU…).

## Détail de la phase 1 : l’opcode fetch

1. Le contenu du **PC** est envoyé sur le **bus d’adresses**.
2. L’unité de contrôle envoie le signal de **lecture mémoire** (RD).
3. L’octet rangé à l’adresse égale au PC est placé sur le **bus de données**.
4. Le **RI** récupère cet octet : c’est le **code opératoire**.
5. Le **séquencement interne** peut alors débuter.

Cette phase s’appelle l’**OPCODE FETCH**.

## Séquencement : le compteur programme (PC)

Une instruction occupe 8, 16 ou 24 bits : l’unité de commande lit en mémoire les octets suivants si besoin. C’est l’unité de commande qui pilote tout ce séquencement.

<Property titre="Cas général : séquentiel">
    $$
    PC \leftarrow PC + 1
    $$

    Le PC pointe sur le mot suivant de la mémoire programme. Exemple Z80 : à l’adresse 2000h, `LD A,B` donne ensuite PC = 2001h ; à 2001h, `INC A` donne PC = 2002h.
</Property>

<Property titre="Exception : JUMP, CALL…">
    $$
    PC \leftarrow @\,\text{cible}
    $$

    L’instruction charge l’adresse cible dans le PC. Exemple Z80 : à l’adresse 2002h, `JP 2025h` donne PC = 2025h, au lieu de 2005h (PC + 3).
</Property>

## Exercice : retrouver le programme

<Exercise titre="Décoder un binaire Z80" niveau={2}>
    On lit en mémoire, à partir de l’adresse 0000h, les octets suivants :

    ```
    47 48 3E 15 4F C3 50 10
    ```

    Pour chaque adresse, retrouver la fonction de l’octet (code opératoire ou opérande) et l’instruction assembleur correspondante, à l’aide de la table des opcodes du Z80. Dans cette table, `n` désigne un octet de donnée et `nn` une adresse de 16 bits, **octet de poids faible en premier**.

    <Solution>
        {/* AJOUT : correction (la diapo de correction est vide) ; le même programme apparaît dans la capture du simulateur, part1.pdf p. 37 */}

        | Adresse | Code (hexa) | Fonction | Assembleur |
        | --- | --- | --- | --- |
        | 0000h | 47 | code opératoire | `LD B,A` |
        | 0001h | 48 | code opératoire | `LD C,B` |
        | 0002h | 3E | code opératoire | `LD A,15h` |
        | 0003h | 15 | opérande (n) | |
        | 0004h | 4F | code opératoire | `LD C,A` |
        | 0005h | C3 | code opératoire | `JP 1050h` |
        | 0006h | 50 | opérande (poids faible de nn) | |
        | 0007h | 10 | opérande (poids fort de nn) | |

        Le programme copie A dans B, puis B dans C, charge 15h dans A, copie A dans C et saute à l’adresse 1050h.
    </Solution>
</Exercise>

## L’endianness

<Definition titre="Endianness">
    L’endianness est l’**ordre des octets en mémoire** d’une valeur qui en occupe plusieurs.

    - **Big-Endian** : l’octet de poids fort est rangé en premier.
    - **Little-Endian** : l’octet de poids faible est rangé en premier.
    - **Bi-Endian** : l’ordre est configurable.
</Definition>

<Example titre="La valeur (A1B2C3D4)h en mémoire">
    | Adresse | +0 | +1 | +2 | +3 |
    | --- | --- | --- | --- | --- |
    | Big-Endian | A1 | B2 | C3 | D4 |
    | Little-Endian | D4 | C3 | B2 | A1 |
</Example>

| Endianness | Microprocesseurs | Systèmes d’exploitation |
| --- | --- | --- |
| Little-Endian | Intel x86, Zilog Z80 | Android, iOS, Windows sur x86 et MIPS |
| Big-Endian | Motorola 68000, Atmel AVR32 | Mac OS sur PowerPC, Linux sur MIPS |
| Bi-Endian | ARM, MIPS | — |

## Exercice : expliquer un programme

<Exercise titre="Trouver et expliquer le programme" niveau={3}>
    Le contenu de la mémoire, vu dans l’éditeur mémoire du simulateur, est le suivant à partir de l’adresse 0000h :

    ```
    0000: 79 EE FF F6 10 4F E6 80 C2 27 20 00 00 00 00 00
    ```

    Trouver et expliquer le programme correspondant.

    <Solution>
        | Adresse | Octets | Z80 | Effet |
        | --- | --- | --- | --- |
        | 0000 | 79 | `LD A,C` | A ← C |
        | 0001 | EE FF | `XOR FFh` | A ← complément de A |
        | 0003 | F6 10 | `OR 10h` | met le bit 4 à 1 |
        | 0005 | 4F | `LD C,A` | C ← A |
        | 0006 | E6 80 | `AND 80h` | teste le bit 7 |
        | 0008 | C2 27 20 | `JP NZ,2027h` | saute si le bit 7 vaut 1 |
        | 000B | 00 | `NOP` | |
    </Solution>
</Exercise>
