## Le protocole DNS

### Au temps de l'ARPANET… étaient les fichiers hosts !

<Remark titre="Point historique">
    Avant le DNS, pour connaître les noms associés aux adresses, on s'échangeait des fichiers.
</Remark>

<Example titre="Exemple de fichier /etc/hosts">
    ```
    127.0.0.1 localhost
    127.0.1.1 segonzac.intranet.example.net segonzac
    ::1 localhost ip6-localhost ip6-loopback
    ```
</Example>

Structure du fichier `/etc/hosts` : une adresse IP ; un nom d'hôte principal ; un ou plusieurs alias. Exemple : `127.0.1.1 host.localdomain host`.

### Au temps des universités US

**Problème** :

- un fichier à distribuer à toutes les machines…
- dans toutes les universités…
- ça devient pénible, et Stanford invente le **Domain Name System**…
- … et Berkeley son implémentation **Berkeley Internet Name Domain** (BIND).

### Les Top Level Domains

Quelques exemples :

- domaines historiques (`.net`, `.org`, `.com`…) ;
- domaines ouverts (`.info`, `.ovh`, `.clothing`…) ;
- domaines parrainés (`.edu`, `.gov`, `.gouv.fr`, `.travel`…) ;
- domaines restreints (`.biz`, `.pro`, `.name`…) ;
- domaines privés (`.leclerc`, `.sncf`, `.axa`…) ;
- domaines nationaux (`.fr`, `.re`, `.us`, `.de`…).

### Les domaines de premier niveau spéciaux

Bonne question, merci de l'avoir posée ! Lesquels ?

| TLD | Usage |
| --- | --- |
| `.invalid` | pour marquer explicitement comme invalide (RFC 6761) |
| `.arpa` | utilisé pour les zones inverses |
| `.example` | pour la documentation (RFC 6761) (parfois bloqué !) |
| `.localhost` | pour les adresses de loopback (RFC 6761) |

| `.lan` | réseau local MAIS n'est pas officiel ! |
| `.onion` | sites du réseau Tor (RFC 7686) (hors DNS classique) |
| `.test` | pour les laboratoires (RFC 6761) |

### Les Second Level Domains

- Domaines attachés à un domaine de premier niveau.
- Frontière du domaine privé.
- Contient autant de sous-domaines que nécessaires…
- … qui eux-mêmes peuvent contenir des sous-domaines, etc.

### Les racines alternatives

<Definition titre="Racines du DNS">
    Le *Domain Name System*, implicitement, fait référence à l'ICANN et aux 13 serveurs racine couramment utilisés.
</Definition>

Il existe d'autres racines :

- **AlterNIC** : était le concurrent d'InterNIC avant la création de l'ICANN. Décédé.
- **Handshake** : est un système décentralisé fondé sur une blockchain, avec objectif de résilience, et complément au DNS classique.
- **Namecoin** : est un système décentralisé fondé sur une blockchain, spécifique au TLD `.bit`.
- **OpenNIC** : est une racine DNS alternative, fondée sur le mécanisme DNS classique, mais sans lien avec les racines de l'ICANN et de l'IANA.
- **Souverains** : Yeti DNS Project, `.chn`, Russian National Domain Name System.

### Types d'enregistrements

<Definition titre="Resource Records">
    Le DNS utilise des *Resource Records* pour catégoriser l'information et la distribuer.
</Definition>

Un enregistrement est un nom qui associe différentes données, par exemple : des adresses IPv4 ; des adresses IPv6 ; des clés SSH ; du texte libre…

Enregistrements les plus courants :

| Type | Contenu |
| --- | --- |
| A | adresse IPv4 |
| AAAA | adresse IPv6 |
| PTR | nom réel (à partir d'une adresse) |
| SOA | racine d'une zone autoritaire |
| CNAME | alias |
| NS | serveurs de noms autoritaires |
| MX | relais de courrier |
| TXT | texte libre |
| DS | signature de zone (DNSSEC) |

### Start Of Authority (SOA)

<Definition titre="SOA">
    Indique qu'un serveur fait autorité pour un sous-domaine donné.
</Definition>

| Champ | Signification |
| --- | --- |
| Master NS | serveur maître de zone |
| Contact | adresse de courriel du gestionnaire du serveur maître |
| Serial | numéro de version pour la zone |
| Refresh | écart en secondes pour les mises à jour (secondaires, esclaves) |
| Retry | délai en secondes entre deux requêtes si la première a échoué |
| Expire | délai en secondes pour déclarer la zone invalide si le primaire est injoignable |
| Min. TTL | durée de vie en secondes d'une réponse dans le cache |
| Neg. TTL | durée de vie en secondes des demandes d'enregistrements inexistants |

### Circulation de la requête

1. Le client se pose une question : `www.free.fr ?` Il envoie sa requête à son serveur de rattachement.
2. Le résolveur ne connaît pas ce nom ni cette racine. Il demande à un serveur racine qui gère ce TLD.
3. Le serveur racine le renvoie vers un serveur autoritaire .FR.
4. Le serveur repose sa question pour le domaine de second niveau.
5. Une nouvelle autorité est renvoyée, celle de Free.
6. Le serveur interroge les DNS de Free, désormais connus.
7. La réponse définitive est enfin obtenue…
8. … et renvoyée au client.

### Client DNS sous Windows

<Definition titre="Client DNS">
    Il centralise les requêtes au DNS pour proposer du cache ou parfois un peu « d'intelligence ».
</Definition>

Sous Windows, un service appelé « Client DNS » permet d'effectuer ces opérations. Sans lui, les résolutions fonctionnent moins bien (voire pas du tout selon les versions). Peut se manipuler avec des CmdLets PowerShell.

### Client DNS historique sous Linux

Les fichiers très historiques de Linux sont interfacés par le « *Name Service Switch* », dont le fameux `/etc/hosts`.

- Le client historique correspond essentiellement (et par raccourci) à NSSwitch.
- Un cache peut lui être ajouté : NSCD, *Name Service Caching Daemon*.
- Bascule entre les fichiers (`hosts`, `resolv.conf`) et le DNS (entre autres).

### Client DNS de systemd : systemd-resolved

**Objectif** : éliminer certains mécanismes obsolètes ou plus maintenus activement.

Fonctionnement général :

- il agrège des sources de noms différentes ;
- il émule un résolveur local ;
- il fait du cache et de la signature ;
- il remplace `/etc/resolv.conf` par un lien symbolique.

<Example titre="Exemple de configuration simple et largement utilisé">
    ```ini
    [Resolve]
    DNS=192.168.1.254
    Cache=yes
    DNSStubListener=yes
    ReadEtcHosts=yes
    ```
</Example>

## Bonus : le protocole VRRP

<Definition titre="Virtual Router Redundancy Protocol (VRRP)">
    Affecter une IP « flottante » à plusieurs routeurs ou plusieurs services afin d'avoir un « actif » et un (ou plusieurs) « secours ».
</Definition>

Fonctionnement :

- les systèmes s'entendent sur la possession d'un jeton qui autorise à utiliser l'adresse IP ;
- les participants s'annoncent via une adresse de multicast ;
- les participants s'attribuent une adresse MAC virtuelle ;
- des paquets ARP gratuits permettent de reprendre le contrôle de l'IP virtuelle en cas de bascule.

## Bonus : le protocole IPSec

<Definition titre="Internet Protocol Security (IPSec)">
    Signer ou chiffrer les paquets IP.
</Definition>

**Fonctionnement** : un « contexte de sécurité » (ou association de sécurité) définit le fait de chiffrer le flux pour un ou plusieurs sous-réseaux IP avec une clé donnée.

**Protocoles** : la négociation des clés est généralement effectuée par *Internet Key Exchange* (IKE). Selon les implémentations, l'authentification peut être réalisée par *Extensible Authentication Protocol* (EAP) et ses modules.

## HTTP, le protocole à tout faire (ou pas !)

<Definition titre="HyperText Transfer Protocol (HTTP)">
    **Principe le plus élémentaire** : transporter des données de différents formats sur le Web.

    **Principe actuel** : transporter des pages Web et leur contenu (voire plus).
</Definition>

### Fonctionnement

<Example titre="Requête HTTP simple">
    ```http
    GET / HTTP/1.1
    Host: www.perdu.com
    ```
</Example>

Quelques verbes / méthodes : `GET`, `POST`, `HEAD`, `PUT`, `DELETE`, `CONNECT`…

- **Mode de fonctionnement** : HTTP est un protocole **sans état**… comme UDP donc !
- **En-têtes** : les en-têtes, notamment les cookies, permettent de créer un mode connecté, donc de poursuivre une « session » vue de l'application Web… comme TCP donc !

### Utilisation

Il est tellement répandu qu'il a été adapté à de nouveaux usages :

- **WebDAV** : transferts de fichiers montants et descendants (dont CalDAV et CardDAV) ;
- **WebServices** : flux machine-to-machine (REST, SOAP…) ;
- **WebSockets** : flux full-duplex entre clients et serveur (dont streaming) ;
- **WebRTC** : flux peer-to-peer multimédia entre navigateurs (dont RTP) ;
- **DNS over HTTP (DoH)** : pour contourner la censure DNS.

Il en est devenu difficile à filtrer !
